## Activation and storage

`config/iot.php` defaults `IOT_API_ENABLED` to false. An ordinary installation
returns a redacted 503 until the owner approves migration and activation.
Configuration caching captures this flag in the normal Laravel configuration.
The current owner's `.env` is not changed by this task.

One forward migration adds only `iot_devices` and `iot_request_nonces`.
The migration was created for isolated tests. A real MariaDB migration requires
separate owner approval. Device rows contain a stable lowercase UUID v4, a
non-secret label, an encrypted independent 256-bit key, its version and nullable
revocation timestamp. Revoked devices cannot rotate back to active. Provision a
new identity when replacing a revoked device.

Laravel's encrypted cast wraps device keys with the application's encryption key.
APP_KEY is never a device signing key. Protect both database backups and APP_KEY.
Losing the wrapping key requires device reprovisioning unless a valid previous
Laravel encryption key remains configured. Recoverable encryption is required
because ordinary HMAC verification needs the original signing key.

Replay state is a database table with a unique `(device_id, nonce_hash)` index,
a device foreign key and indexed UTC expiry. It stores SHA-256 of each nonce and
no request body, signature, QR credential or Resident information. Database cache
provides the existing native Laravel rate-limiter storage. Replay correctness
does not depend on cache eviction, process-local state or a cache add fallback.
Production must retain a shared cache backend and an InnoDB device/nonce schema.

## Exact firmware protocol

| Item | Contract |
| --- | --- |
| Method | `POST` |
| Path | `/api/iot/v1/probe`, exact bytes, no query string or trailing slash |
| Content-Type | `application/json`, optional `; charset=utf-8` |
| Content-Encoding | Absent or `identity` |
| Maximum body | 1024 bytes, including whitespace |
| Body | JSON object containing only `"message":"probe"` |
| X-SB-Device | Lowercase UUID v4, 36 ASCII characters |
| X-SB-Key-Version | Decimal integer 1 through 999999999, no leading zero |
| X-SB-Timestamp | Unix UTC seconds, 10 decimal digits |
| X-SB-Nonce | 16 random bytes encoded as 32 lowercase hex characters |
| X-SB-Signature | HMAC-SHA256 encoded as 64 lowercase hex characters |
| Clock window | Timestamp within inclusive plus/minus 90 seconds of server UTC |

All five authentication headers are required exactly once. Combined, repeated,
oversized or malformed header values fail authentication. Content length is checked
when supplied. A bounded input-stream check runs before global JSON transformations.
The exact original body bytes are hashed, including whitespace and any final newline.

Canonical input is UTF-8/ASCII text with LF separators and **no trailing LF**.
These are the exact eight lines, in order.

```text
SB-IOT-1
POST
/api/iot/v1/probe
<X-SB-Device>
<X-SB-Key-Version>
<X-SB-Timestamp>
<X-SB-Nonce>
<lowercase SHA256 hex of exact HTTP body bytes>
```

Decode `key_hex` from the private provisioning JSON into 32 binary bytes before
HMAC. Do not HMAC with the 64 ASCII hex characters. Use constant-time comparison
on the server. Neither host nor scheme enters this representation, so each key
must be exclusive to one installation and must never be reused across deployments.
HTTPS certificate validation authenticates the intended server.

Example harmless body bytes, with no trailing newline follow.

```json
{"message":"probe"}
```

Success is HTTP 200, with this response shape. Values are generated by the server.

```json
{"ok":true,"api_version":"1","request_id":"<UUID>","server_time":"<UTC ISO8601 ending Z>"}
```

Responses carry `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`.
They create no session cookie and return no device key, nonce or device identifier.

| HTTP status | Error code |
| --- | --- |
| 400 | `invalid_request` for malformed JSON or noncanonical request URI |
| 401 | `authentication_failed` for all identity/key/signature/time/replay failures |
| 403 | `secure_transport_required` |
| 404 | `not_found` |
| 405 | `method_not_allowed`, with Allow header |
| 413 | `request_too_large` |
| 415 | `unsupported_media_type` |
| 422 | `invalid_probe` for an invalid JSON shape or message |
| 429 | `rate_limited`, with Retry-After |
| 503 | `service_unavailable`, including disabled API or backend failure |

Errors have exactly `{"ok":false,"error":"<code>"}`. Debug traces, SQL bindings,
exception details and authentication headers are suppressed for IoT API errors.
Route-specific exception reporting suppression prevents sensitive request context
from being added to ordinary exception logs. Operational monitoring should use
status counts and fixed categories, with request-header/body capture disabled.

The pre-authentication limit is 60 requests per minute per actual TCP peer address,
using REMOTE_ADDR rather than forwarded client headers. Successful authentication
is additionally limited to 30 requests per minute per device. Laravel's native
limiter is an abuse control, not a strict concurrent quota. An authenticated
request consumes its nonce before the per-device limit, so a 429 retry needs a
new nonce and signature after Retry-After.

## Replay, rotation and concurrency

Authentication locks the device row, rechecks revocation/version/time, decrypts
the key, compares HMAC and inserts the nonce in one transaction. Rotation and
revocation lock that same row. The database unique constraint rejects duplicates
across workers. A failed signature cannot reserve a nonce. Authentication that
completed before revocation is ordered before revocation by that lock.

Nonce expiry equals signed timestamp plus 91 seconds. A request signed 90 seconds
ahead can remain acceptable for up to 180 seconds, so retaining only 90 seconds
after first receipt would be unsafe. Expired nonces are removed hourly by
`smartbarangay:prune-iot-nonces`, gated by the API enable flag. Old timestamps
remain invalid after pruning. Actual production scheduler execution requires
separate configuration. Cleanup failure retains rows and fails safely.

The isolated concurrency test starts two PHP HTTP kernels against one temporary
SQLite database. Exactly one duplicate succeeds. A SQLite lock/contention error
may return redacted 503. InnoDB row-lock/concurrency runtime acceptance still
requires a controlled MariaDB test environment.

## Controlled provisioning commands

These are future owner-operated commands after approved migration, not commands
to run against the real database during this milestone. Create a private directory
outside htdocs first. The output file must be new and its parent must exist.

The parent must already grant access only to the current Windows identity and
SYSTEM. POSIX parents must have no group/other permissions. Provisioning checks
this before creating the file. For a new owner-controlled Windows directory,
the following setup can be performed at the later approved provisioning stage.

```powershell
$privateDirectory = "$env:USERPROFILE\.smartbarangay\iot-devices"
New-Item -ItemType Directory -Path $privateDirectory
$ownerSid = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
icacls $privateDirectory /inheritance:r /grant:r "*${ownerSid}:(OI)(CI)F" '*S-1-5-18:(OI)(CI)F'
```

```powershell
php artisan smartbarangay:iot-device provision --name="Scanner 01" --output="C:\Users\ronin\.smartbarangay\iot-devices\scanner-01-v1.json"
php artisan smartbarangay:iot-device rotate <device-uuid> --output="C:\Users\ronin\.smartbarangay\iot-devices\scanner-01-v2.json"
php artisan smartbarangay:iot-device revoke <device-uuid>
```

Provisioning can optionally take an explicit lowercase UUID v4, and duplicate
identities fail. The generated secret is written only to the private JSON file.
Windows file ACLs remove inherited access and grant the current Windows identity
and SYSTEM. POSIX permissions are 0600. Permission setup must succeed before
secret bytes are written. Existing files and htdocs destinations are rejected.
On failed issuance, the database transaction rolls back and the new output file
is removed. Console messages omit the key and database exception details.

Private JSON contains `device_id`, `key_version`, `key_hex`, `protocol`. Transfer
it through a private channel only during a separately authorized firmware setup.
Rotation atomically replaces the encrypted key and increments its version. Old
credentials then fail even when timestamps and nonces are fresh. Keep the new file
private. If a database connection fails ambiguously during commit, reconcile the
device row and issue another controlled rotation rather than guessing which key
became active. Revocation is idempotent.

## Firmware and hosting requirements for subsequent milestones

ESP32-CAM needs a CSPRNG nonce, SHA-256/HMAC, exact JSON byte handling, the
provisioned independent key/version/identity and a valid UTC clock. Synchronize
time at startup, reject implausible time, periodically resynchronize, and send no
authenticated requests until clock synchronization succeeds. NTP is not a reason
to bypass timestamp checks. Server clocks must also be monitored for drift.
On timeout, generate a new nonce for the next probe. This harmless endpoint has
no retryable business side effect.

Physical communication requires certificate-validated HTTPS. No TLS verification
bypass belongs in firmware. The current API checks direct server HTTPS, ignoring
forwarded scheme headers. Reverse-proxy deployments need a separately reviewed
trusted-proxy/TLS boundary. Plain HTTP is accepted only from an actual loopback
peer in Laravel local/testing environments, for bounded development simulation.

The unresolved shared Apache source/archive exposure remains a rollout blocker.
Protect the public-only web root and private database/key material before real
device or Resident QR traffic. Provisioned JSON must stay outside htdocs, separate
from both Laravel `.env` and the firmware's existing private Wi-Fi header. Existing
firmware metadata/mode servers remain standalone test surfaces.

## Future Admin pairing contract

IoT-02 stores device identities, encrypted keys, revocation and replay nonces only.
A later milestone must persist a temporary scanner lease bound to exactly one
active, verified Admin and one server-side browser-session identity. A unique
active device lease must be acquired atomically, with explicit expiry/revocation.
Logout, password/session invalidation, account deactivation, timeout, device
revocation and workstation release must invalidate the lease and pending handoffs.

Fresh scan events need device identity, boot/session/sequence discriminator,
short expiry and idempotency. Laravel must verify the actual SBQ1 credential via
the existing QrTicketVerifier and mint an opaque, expiring, single-use handoff
bound to the lease, device, Admin and browser session. Claim must atomically check
all bindings and freshness, reverify the ticket and create the existing five-minute
Admin-bound verification evidence. A different workstation cannot claim or read
that result. Device-provided Admin/reservation IDs never establish authority.
Explicit Admin confirmation still calls CheckInReservations. Payment, documents
and completion retain their existing independent transactions.
